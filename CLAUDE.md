# CLAUDE.md — AI Assistant Guide for digitalocean-openvpn

This file provides context for Claude (or any AI assistant) to understand the project structure, conventions, and how to make changes safely.

---

## Project Overview

This project automates deploying an OpenVPN server on DigitalOcean using:
- **Terraform** — provisions the DigitalOcean Droplet, SSH key, and firewall
- **Ansible** — installs and configures OpenVPN, EasyRSA PKI, and manages clients
- **Shell scripts** — orchestration glue and user-friendly wrappers
- **Makefile** — unified entry point for all operations

---

## Architecture Summary

```
User → Makefile / scripts/ → Terraform (provision VPS) → Ansible (configure VPN)
                            ↓
                    DigitalOcean API
                    Creates: Droplet, Firewall, SSH Key, Reserved IP (optional)
                            ↓
                    Ansible connects via SSH
                    Installs: openvpn, easy-rsa
                    Configures: PKI, server.conf, UFW, sysctl
                    Generates: client .ovpn files
```

## Key Files and Their Purpose

### Terraform (`terraform/`)

| File | Purpose |
|------|---------|
| `main.tf` | Droplet, firewall, SSH key, reserved IP, generates Ansible inventory |
| `variables.tf` | All input variables with descriptions and defaults |
| `outputs.tf` | Server IP, SSH command, inventory path |
| `inventory.tpl` | Template used to generate `ansible/inventory/hosts.ini` |
| `terraform.tfvars.example` | User-facing config example (copy to `terraform.tfvars`) |

### Ansible (`ansible/`)

| File/Dir | Purpose |
|----------|---------|
| `ansible.cfg` | Ansible settings (inventory path, SSH args, etc.) |
| `group_vars/all.yml` | Global variables: port, cipher, network, domain, EasyRSA version |
| `roles/openvpn_server/` | Server installation and configuration role |
| `roles/openvpn_client/` | Client certificate generation and .ovpn creation |
| `setup.yml` | Main playbook: runs openvpn_server role |
| `add-client.yml` | Creates client cert + .ovpn file |
| `revoke-client.yml` | Revokes a client certificate |
| `list-clients.yml` | Lists all client certificates and status |
| `update-openvpn.yml` | Updates OpenVPN and optionally EasyRSA |
| `inventory/hosts.ini` | Auto-generated by Terraform; lists server IP |

### Ansible Role: `openvpn_server`

```
roles/openvpn_server/
├── defaults/main.yml      # Role defaults (overridden by group_vars/all.yml)
├── handlers/main.yml      # Service restart/reload handlers
├── tasks/
│   ├── main.yml           # Includes all task files in order
│   ├── install.yml        # apt install openvpn, download/symlink EasyRSA
│   ├── pki.yml            # init-pki, build-ca, gen-req server, sign-req, gen-dh, ta.key
│   ├── configure.yml      # Deploy server.conf, enable IP forwarding, start service
│   └── firewall.yml       # UFW rules, NAT masquerade, allow VPN/SSH ports
└── templates/
    ├── server.conf.j2     # OpenVPN server configuration
    ├── vars.j2            # EasyRSA vars file
    └── sysctl-openvpn.conf.j2  # IP forwarding sysctl settings
```

### Ansible Role: `openvpn_client`

```
roles/openvpn_client/
├── defaults/main.yml      # Role defaults
├── tasks/
│   ├── main.yml           # Creates client cert, generates .ovpn, fetches to local
│   └── revoke.yml         # Revokes cert, regenerates CRL, reloads OpenVPN
└── templates/
    └── client.ovpn.j2     # Inline .ovpn config with embedded CA, cert, key, tls-crypt
```

## How to Make Common Changes

### Change OpenVPN Port

Edit `ansible/group_vars/all.yml`:
```yaml
openvpn_port: 1194   # Change to desired UDP port
```

Also update `terraform/terraform.tfvars` before provisioning:
```hcl
openvpn_port = 1194
```

Then re-run the server configuration:
```bash
cd ansible && ansible-playbook setup.yml --tags configure,firewall
```

### Change VPN Subnet

Edit `ansible/group_vars/all.yml`:
```yaml
openvpn_server_network: "10.9.0.0"    # New subnet
openvpn_server_netmask: "255.255.255.0"
openvpn_server_network_cidr: "10.9.0.0/24"
```

Re-run configure + firewall tags:
```bash
cd ansible && ansible-playbook setup.yml --tags configure,firewall
```

### Change Encryption Settings

Edit `ansible/group_vars/all.yml`:
```yaml
openvpn_cipher: "AES-256-GCM"      # Server cipher
openvpn_auth_digest: "SHA256"       # HMAC digest
openvpn_tls_version_min: "1.2"     # Minimum TLS version
```

**Important**: Client `.ovpn` files use the same cipher/auth. After changing:
1. Re-run `setup.yml --tags configure`
2. Regenerate all client configs (they inherit from server defaults via `group_vars/all.yml`)

### Update EasyRSA Version

1. Check latest release: https://github.com/OpenVPN/easy-rsa/releases
2. Update `ansible/group_vars/all.yml`:
   ```yaml
   easyrsa_version: "3.1.7"   # New version
   ```
3. Run the update playbook:
   ```bash
   cd ansible && ansible-playbook update-openvpn.yml \
     --extra-vars "update_easyrsa=true new_easyrsa_version=3.1.7"
   ```

### Add a New DigitalOcean Region

The region is set in `terraform/terraform.tfvars`. No code changes needed.
Valid regions are listed in the README.

### Add IPv6 Support

In `ansible/roles/openvpn_server/templates/server.conf.j2`, add:
```
proto udp6
```
(or add a separate IPv6 listener).

Update firewall rules in `tasks/firewall.yml` to allow IPv6 inbound.

### Change DNS Servers Pushed to Clients

Edit `ansible/group_vars/all.yml`:
```yaml
openvpn_dns_servers:
  - "8.8.8.8"    # Google
  - "8.8.4.4"
```

Re-run: `cd ansible && ansible-playbook setup.yml --tags configure`

## Conventions and Patterns

### Variable Naming
- All OpenVPN-related Ansible variables are prefixed with `openvpn_`
- EasyRSA variables are prefixed with `easyrsa_`
- Terraform variables use underscores (e.g., `do_token`, `droplet_region`)

### Idempotency
All Ansible tasks are designed to be idempotent (safe to run multiple times):
- PKI setup checks for existing files before creating
- `stat` + `when: not result.stat.exists` pattern used throughout
- Certificate generation is skipped if the cert already exists

### Error Handling
- Scripts use `set -euo pipefail` for strict error handling
- Ansible tasks use `register` + `failed_when` for controlled failures
- Critical prerequisites are validated in `pre_tasks` blocks

### Template Variables
Jinja2 templates in `templates/` can use any variable from:
1. `ansible/group_vars/all.yml` (global)
2. `roles/*/defaults/main.yml` (role defaults)
3. Extra vars passed via `--extra-vars`
4. Facts gathered from the target host (`ansible_host`, `ansible_distribution`, etc.)

## Adding New Functionality

### Adding a New Playbook

1. Create `ansible/<name>.yml`
2. Follow the pattern of existing playbooks (pre_tasks for validation, role or tasks, post_tasks for summary)
3. Add a corresponding script `scripts/<name>.sh` if user-facing
4. Add a `make` target in `Makefile`
5. Document in README.md

### Adding a New Ansible Task to Server Setup

1. Create a new task file in `ansible/roles/openvpn_server/tasks/<name>.yml`
2. Include it in `ansible/roles/openvpn_server/tasks/main.yml`:
   ```yaml
   - name: Include <name> tasks
     include_tasks: <name>.yml
     tags: [<name>, openvpn]
   ```

### Adding a New Terraform Resource

1. Add the resource to `terraform/main.tf`
2. If it requires a new input, add a variable to `terraform/variables.tf` with a sensible default
3. If the resource produces useful output (e.g., an IP, ID), add it to `terraform/outputs.tf`
4. Update `terraform/terraform.tfvars.example` with the new variable

## Testing Changes

Since this project provisions real cloud infrastructure, test carefully:

1. **Terraform dry run**: `make plan` — shows what will change without applying
2. **Ansible check mode**: `cd ansible && ansible-playbook setup.yml --check` — simulates changes
3. **Tag-based runs**: Use `--tags` to run only specific parts:
   ```bash
   ansible-playbook setup.yml --tags configure    # Only re-configure
   ansible-playbook setup.yml --tags firewall     # Only update firewall
   ansible-playbook setup.yml --tags pki          # Only PKI setup
   ```
4. **Verify service**: After changes, run `make status` and `make logs`

## File Gitignore Rules

The following are intentionally excluded from git:
- `terraform/terraform.tfvars` — contains API token (secret)
- `terraform/.terraform/` — Terraform plugin cache
- `terraform/terraform.tfstate*` — Terraform state (manage remotely for teams)
- `ansible/inventory/hosts.ini` — auto-generated from Terraform output
- `clients/` — generated .ovpn files contain private keys

## Common Gotchas

1. **DH parameter generation is slow** — `gen-dh` can take 1-5 minutes. The task uses `async/poll` to handle this.

2. **EasyRSA PKI path** — EasyRSA uses `/opt/easy-rsa/pki/` as its PKI directory (set via `EASYRSA_PKI` env var). Don't confuse with `/etc/openvpn/`.

3. **Client .ovpn cert extraction** — The client cert PEM file from EasyRSA contains extra text before the `-----BEGIN CERTIFICATE-----` block. The template uses `regex_replace` to strip this.

4. **UFW before.rules** — NAT masquerade rules must go in `before.rules` (before UFW's default rules), not in the standard UFW command interface.

5. **Terraform inventory generation** — The `local_file` resource writes `ansible/inventory/hosts.ini`. If you destroy and recreate infrastructure, this file is regenerated automatically.

6. **OpenVPN UDP vs TCP** — UDP is always primary. TCP is optional (`openvpn_enable_tcp`). Both the Terraform firewall and UFW rules need updating when TCP is enabled.
